## Current answer

Asset Shepherd is **not yet compliant in all respects as a finished submission**. No current
implementation choice appears inherently disqualifying: the repository was created during the
submission period, the product uses Strands Agents for a genuine agent-directed workflow, and it
does end-to-end asset work rather than merely discussing it. The remaining gaps are release and
submission gates: the repository is private, remote judge access is not ready, the final
architecture artifact and public video do not exist, the submission text is not frozen, and some
eligibility, registration, ownership, and support facts require the entrant's attestation.

Status meanings:

- **PASS:** repository or test evidence currently supports the requirement.
- **IN PROGRESS:** eligible direction, but final evidence or deployment is incomplete.
- **GAP:** a mandatory submission item does not exist yet.
- **HUMAN CONFIRMATION:** only the entrant can truthfully establish the fact.
- **OPTIONAL:** not required for eligibility, though it may improve scoring.

## Interpretations that affect this project

### Strands and model provider

The rules require a real agent built with Strands Agents. They do not require an Anthropic model,
Bedrock Converse, or any particular foundation-model provider. Asset Shepherd may use GPT-5.6 Luna
through Amazon Bedrock's Responses-compatible interface as long as Strands remains the genuine
orchestrator and the integration obeys its applicable terms. AgentCore deployment and a live demo
are optional, but either can strengthen the Technical Implementation score. Free working-project
access during judging is mandatory even though the separate Devpost **live demo link** field is
described as optional.

The selected production path is not implemented yet. The current environment-selected Bedrock path
constructs Strands `BedrockModel` over Converse, while D071 selects a Responses-compatible adapter
for Luna/xhigh parity. Do not claim all-Bedrock parity until that adapter and constrained intake tool
pass image, sequential-tool, approval/resume, validation, and usage-reporting tests.

### New work and disclosure

The repository began after the submission period opened. Standard libraries, frameworks,
templates, and AI coding assistants are permitted. The submission must nevertheless disclose
material pre-existing code or work incorporated into the project. Before release, create a short
disclosure covering dependencies, vendored `<model-viewer>`, generated or external assets,
development assistance, and any reusable templates. Do not imply that Blender, Unreal, Tripo,
OpenAI, or AWS code is owned by the entrant.

### AWS credits and other support

The official rules expressly offer entrant AWS promotional credits, so those contest credits are
part of the authorized program. Record the source and terms of the user's separate $100 credit.
If it was project-specific preferential support from AWS outside the public contest or normal
account promotion, ask the organizer for written clarification before submission. The entrant must
also confirm that the project was not funded, commissioned, commercially licensed, or otherwise
preferentially supported by AWS or Devpost in a way prohibited by the rules.

### Optional Builder posts

Stage Two submissions can earn 0.2 points per public `builder.aws.com` post, up to 0.6 points. The
rules page says it was updated on August 12 to remove the `#AgentsforHumans` requirement, although
lower text still awkwardly says to use “Agents for Humans” in the title. The safe interpretation is
to put the plain words **Agents for Humans** in each title without treating a literal hashtag as a
requirement. Capture the final rule page and post URLs with the submission evidence.

## Mandatory release gates

### Gate 0 — Entrant and registration attestation

- Confirm age of majority and eligible residence.
- Confirm no excluded sponsor/administrator/judge affiliation or conflict.
- Confirm entrant type and authorized representative, if applicable.
- Confirm Devpost registration, hackathon join state, and AWS Builder ID.
- Record the provenance of AWS credits and any other financial or preferential support.
- Review and accept the rules' publicity, non-exclusive judging license, identity verification,
  winner-form, prize-allocation, and tax obligations; confirm no confidential submission material.

This private attestation records pass/fail only. Do not commit personal addresses, identity
documents, account IDs, emails, tax information, or Devpost credentials.

### Gate 1 — Eligible build proof

- Preserve the Git history showing the August 21 project start.
- Complete one Bedrock-hosted Strands run without direct OpenAI fallback.
- Export a bounded trace proving agent-directed tool use, exact approval, mutation, independent
  verification, and packaging without exposing chain-of-thought or secrets.
- Add the pre-existing-work, dependency, asset, and technical-assistance disclosure.
- Confirm every third-party component and demo asset is authorized for public redistribution and
  presentation.

### Gate 2 — Public repository proof

- Run the common quality gate from a clean clone.
- Verify every required runtime file is tracked or reproducibly fetched/generated by documented
  commands; do not depend on local `build/web/jobs`, Downloads, browser state, or ignored evidence.
- Run a license/attribution audit, dependency vulnerability review, malicious-file scan, and secret
  scan over the full Git history and release tree.
- Make the repository public after those checks.
- From a logged-out browser, verify README/setup, source, required assets, test instructions, and
  the MIT license visible in the GitHub About area.

### Gate 3 — Judge-access proof

- Complete the remote-product gate in `BEDROCK_DEPLOYMENT_RUNBOOK.md`.
- Test upload through download from a logged-out browser with a new asset and a resumed asset.
- Verify restart recovery, per-workspace isolation, explicit approval, bounded failure, and useful
  diagnostics for a deliberately invalid GLB.
- Provide simple free testing instructions and least-privilege demo credentials only if needed.
- Monitor availability, budget, quotas, certificate expiry, storage lifecycle, and errors through
  2026-10-08 5:00 p.m. Pacific. Do not place a paywall, approval queue, or geographic restriction
  in front of judges.

### Gate 4 — Submission package proof

- Freeze the exact public repository commit and judge URL.
- Produce one legible architecture diagram and include it in the repository and Devpost entry.
- Produce a public YouTube/Vimeo video under five minutes that shows the product working end to
  end and explicitly states the problem, audience, and importance.
- Complete English description, features, Built With, Professional Agents track, Builder ID,
  repository URL, testing instructions, architecture, video, and optional blog URLs.
- Verify every visual and quantitative claim against committed evidence.

### Gate 5 — Final freeze and submission

- On September 10, re-read the official rules and record any delta here.
- By September 13, run a full rehearsal from a logged-out machine and preserve timestamps,
  screenshots, output hashes, and URLs in a private submission evidence bundle.
- On September 14, recheck the rules, public URLs, video duration, test access, and Devpost preview.
- Submit before 5:00 p.m. Pacific and record Devpost's receipt.
- Do not alter the judged submission after the deadline unless Sponsor/Devpost explicitly permits
  the narrow change. The public portfolio may evolve, but the judged entry must remain frozen.
